# Ghost Ship — Competitive Scoring Foundation

This version tracks the proposed balanced score locally and only records a leaderboard result after all three levels are completed. It rewards level completion, correct-on-first-try riddles, clean levels and unused attempts; it deducts points for wrong answers and lost attempts, and adds a Level 3 time bonus.

## Current status

- Local score tracking and local Hall of Fame: implemented.
- Supabase client configuration and online leaderboard reading: included.
- Secure online score submission: intentionally NOT enabled yet. Do not add a public `INSERT` policy and do not submit browser-calculated scores directly. A browser user can modify JavaScript and forge a score.
- This is a foundation for a serious leaderboard, not yet a cheat-resistant live competition.

## Connect Supabase for leaderboard reading

1. Create a project at https://supabase.com.
2. In Project Settings → API, copy the Project URL and publishable/anon key.
3. Put those values in `supabase-config.js`. Never put a service-role or secret key in browser code.
4. Run the SQL below in the Supabase SQL Editor.

```sql
create table if not exists public.captain_scores (
  id bigint generated by default as identity primary key,
  player_id uuid,
  nickname text not null check (char_length(nickname) between 1 and 18),
  score integer not null check (score >= 0 and score <= 1000000),
  levels_completed integer not null default 3 check (levels_completed between 0 and 3),
  wrong_answers integer not null default 0 check (wrong_answers >= 0),
  lost_attempts integer not null default 0 check (lost_attempts >= 0),
  first_try_riddles integer not null default 0 check (first_try_riddles >= 0),
  completion_ms bigint,
  created_at timestamptz not null default now()
);

alter table public.captain_scores enable row level security;
grant select on public.captain_scores to anon, authenticated;
create policy "Anyone can read captain leaderboard"
  on public.captain_scores for select to anon, authenticated using (true);
-- Intentionally no public INSERT policy. Only a trusted server-side function
-- should write verified scores after validating a completed run.
```

## Before turning on competitive submissions

Deploy a Supabase Edge Function (for example `submit-captain-score`) that:

- requires a valid authenticated player identity and applies per-player/IP rate limits;
- validates a server-issued run token and the allowed level order/rules;
- verifies the score from server-verifiable run data rather than trusting a client `score` field;
- checks impossible completion times, duplicate submissions and score bounds;
- writes the score using server-side credentials kept only in Edge Function secrets;
- returns only a success/failure result to the client.

For stronger anti-cheat, the game needs server-verifiable actions or replay/event validation; merely moving the same client score calculation into an Edge Function does not make it secure. Keep the service-role key out of `supabase-config.js`.

## Proposed scoring rules (initial balance)

- Level completion: 1,000 / 1,500 / 2,000 points.
- First-try riddle solve: +100 each.
- Clean level (no failed attempt on that level): +200 / +300 / +400.
- Preserved attempts: +100 for each unused attempt.
- Wrong answer: −50.
- Lost attempt: −150.
- Remaining Level 3 time: +10 per second.
- Score cannot fall below zero.

These values are an initial proposal and should be play-tested before announcing an official season.


## v15 testing note
The local Hall of Fame uses a fresh browser-storage key (`ghostShipCaptainsHallV2`) so scores from earlier development tests cannot masquerade as results from the corrected scoring flow. Only fully completed three-level voyages are recorded. Starting a new voyage resets that run's progress; an unfinished run cannot inherit completed levels from the previous voyage.
